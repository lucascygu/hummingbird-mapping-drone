# Oprace 越野样品接力

巡检结束后，一只编号为 HB-01 的样品盒留在低棚底下。蜂鸟可以从上方看清室外路口，小鸭子能进棚取件。小鸭子带盒返回 H 交接垫、退出垫面，蜂鸟在垫上接收样品，越过地面断路，在 R 收件台落稳后交付。观众能看到哪一条新观测改变了路线，也能从记录里追到同一件物品的去向。

本目录承接 Oprace v0.2 和已有的蜂鸟与小鸭子取物设计。到 H 的一段保留原先的取回任务，H 到 R 是本次新增的运送段。首轮可以由两个人用道具完成。载物飞行与两台实机联合运行仍待验证。

## 打开与复现

在浏览器打开本目录的 `index.html`，将 `relay.js` 和 `view.js` 放在同一目录。离线即可运行。默认选择「南口通行」和「B2 · 按需问路」。按「开始演示」连续播放，或按「单步」查阅每次决定。切换路况或策略将开始新的一轮。「导出 JSON」保存本轮已经显示或确认的事件。现场记录需在重置、切换或关闭页面前导出。

在仓库根目录运行以下命令可以复现自动检查。测试使用 Node.js 18 或以上版本和内置测试运行器。

```sh
node --test demos/oprace-relay/relay.test.cjs
```

## 场地与现场彩排

器材包括一张桌子或纸板低棚、两个可移动挡块、一只贴 HB-01 的轻质空盒，以及分别标出 H 垫、断路和 R 收件台的地贴。用胶带在平地围出碎石带并保留南北两个缺口，再用另一条色带划出末段断路。棚内的路面由近处观察。场地以能让已到手的小鸭子转身、平稳带盒通过为准。屏幕上的比例和估算时间仅用于模型比较。

| 彩排环节 | 两人怎么做 | 留下什么 |
| --- | --- | --- |
| 布场 | 一人换挡块位置，另一人只知道样品坐标和候选走廊。H 垫固定为共同参考点。 | 一张带尺子的俯视图、样品编号、实际使用的平台 |
| 看路 | 第一遍选「现场手动回报」和 B1。一人从上方查看并报告两个室外路口，记录员按实际状况点「通行」或「封闭」。 | 带确认时间的观测、地图版本和更新后的路线 |
| 取件 | 小鸭子沿路线走到棚口，近看棚内后再回报。模型允许在此停等或结束。若由人把盒装上小鸭子，在实验笔记里注明。 | 棚内观测、取件时刻、现场视频里的同一编号 |
| 回到 H | 小鸭子把盒送到交接垫。确认盒在垫上后可直接导出，到此已能验收空地信息协同。 | 一条闭环记录，能指出改道依据和样品所在位置 |
| H 到 R | 小鸭子退出。先用停放的机体或标记牌进行人工换手彩排。真机载物能力、固定方式和场地条件得到验证后，再单独演示飞手操控的搬运与落地签收。 | 分别记录道具彩排和实机完成的阶段，核对 R 收到 HB-01 |

两人可按设备分工。一人负责协调端、地图、记录和回放，另一人负责自己熟悉的平台操作。布场前先约定谁放挡块、谁只看观测、谁确认交接。若用蜂鸟原型，请机体负责人核对手持建图条件。小鸭子的实物型号、行走和取件能力都以现场确认为准。遥控小车或手持传感器可先验接口，录像和笔记注明替身。

## 对照与验收

B0 由小鸭子到路口近处查看。B1 在小鸭子出发前巡看两个室外路口。B2 只在分叉处请求查看当前首选路口，收到封闭结果后重算。B1 与 B2 共用最多两次读数和 10 模型米的空中观察预算。低棚遮挡对三组都生效。每组使用相同的场地、地面感知距离和动作规则。

评价空中观察的收益时，终点取 H。比较是否取到并运回、到 H 的总用时、地面里程，以及空中观察的次数和航程。各组在 H 之后使用同样的运送段。全程另验收四笔交接和最终签收。这样可以单独量出蜂鸟让小鸭子少走了多少，以及多花了多少观察时间。

默认南口通行，在此确定性模型中得到以下一轮数值。它们适合复算逻辑；衡量硬件性能需独立实测。

| 观察方式 | 地面到 H 的总里程 | 含观察在内的到 H 时间 | 空中观察航程 |
| --- | ---: | ---: | ---: |
| B0 地面自探 | 12.04 m | 87.3 s | 0 m |
| B1 固定巡看 | 10.07 m | 82.2 s | 6.51 m |
| B2 按需问路 | 10.07 m | 85.6 s | 9.20 m |

换成北口通行，B0 和 B2 都走 9.33 模型米，B2 为一次观察额外花了时间。双口封闭时，B1 可以在小鸭子出发前结束；棚内封闭时，各组都要到棚口才能发现。两种失败均保留样品原位。五种固定路况是功能用例，重复播放同一条记录不会增加独立样本。

第一次现场验收可以盲换北口、南口各一次，再加一次封闭。记录成功、停止和人工介入。完整交付的判据是收件台拿到同一编号，视频与四笔交接顺序一致。若实物只到 H，应把结果记作地面取回；若由人完成航空段，记作换手彩排。

## 地图与记录

候选走廊是带米制长度的图，规划器按最短路径提议去程与回程。关口可处于未知、通行或封闭三种状态。未知的边可以出现在候选路线里，实际跨越要求先取得通行观测。蜂鸟只能观察露天路口；棚内状态由小鸭子在棚口或样品端回报。模型采用地面 0.15 m/s、空中 0.8 m/s 的假设速度，省略姿态、载荷、抓取和定位噪声。

现场模式由记录员逐项确认，不发送设备命令。回报来到之前保留未知状态。导出中 `source` 区分二维仿真和人工现场记录。每条事件含样品 ID、序号、类型、当前持有方、地图版本、路线和模型距离／用时。交接另含 `custody.from`、`custody.to`、`custody.station`。现场记录另附 `confirmedAt` 和 `actualElapsedSeconds`，表示人工确认时间。模型字段 `time` 和 `toPadS` 始终按假设速度计算。样品到垫事件上的 `actualElapsedSeconds` 可作为现场到 H 的记录。

下一次接蜂鸟时，先用一段手持采集的地图回放，验证路口观测能复现同一个改道。现有 `/hummingbird/map/tile` 高度图块每格只保存最高点，未知值为 -32768。要把它接到本演示，还需要把图块对齐到场地，并根据地面证据、机体宽度和净空判断通行；只看格子里有数值并不足够。此目录目前独立于 ROS 2、PX4 和 Open Duck Runtime。

白皮书、硬件与消息语义的项目来源见 [Oprace v0.2 草案](https://github.com/lucascygu/hummingbird-mapping-drone/pull/1) 与[蜂鸟重建分支的空地接口](https://github.com/lucascygu/hummingbird-mapping-drone/blob/bf66f38d019e0151d0d993693415c1abd07bce45/docs/air-ground-cooperation.md)。
